# OKX 順勢回檔決策單機器人

程式 `scripts/bot.py` 負責所有數字與時間;你(AI)只負責執行、照抄報告,以及在有候選方案時做審核。純 Python 標準函式庫,只用 OKX 公開行情,不需要 API 金鑰,不會下單。

## 必須先讓使用者知道的事(第一次使用時說一次)
- 這不是投資建議;決策與盈虧由使用者自己負責。
- 這套規則在歷史回測中的優勢很薄,沒有被證明能穩定獲利。請當成紀律輔助與前瞻測試工具,用小資金。
- 程式會把每張方案當成「假想單」追蹤結果,不管使用者有沒有照做。

## 第一次使用:設定本金
問使用者三件事:本金(USD)、單筆願意虧的比例(建議 ≤ 2%)、槓桿上限(建議 ≤ 3 倍)。然後執行一次(設定會存下來,之後不用再帶):

```
python3 <本 skill 資料夾>/scripts/bot.py --capital 100 --risk-pct 2 --max-lev 3
```

沒設定時預設本金 100 USD、風險 2%、槓桿上限 3 倍。

## 每次執行
1. 在使用者的工作資料夾執行 `python3 <本 skill 資料夾>/scripts/bot.py`(需要能連 `www.okx.com`,約 20–40 秒)。失敗先重試一次;仍失敗就把實際錯誤訊息貼給使用者。
2. 照輸出**最後一行 `NEXT=`** 的指示做:
   - `NEXT=SEND`:把 `===REPORT===` 與 `===END===` 之間的文字原封不動回覆給使用者,不做其他事。
   - `NEXT=REVIEW`:照下面「有候選方案時的審核」做。

## 鐵則
- 所有價位、金額、賺賠比、時間只能原封不動複製程式輸出。不可心算、不可憑記憶、不可用網頁上的價格取代、不可自己補充其他標的或行情評論。
- 報告固定是「白話摘要」在前、「決策單」在後,不要改格式。
- 行情抓不到時只回報錯誤,不給任何價位。

## 有候選方案時的審核
程式印出 `===CANDIDATE===` 區塊時,做下面四項檢查。有子代理(subagent)工具就平行各開一位、把 CANDIDATE 全文貼給它;沒有就自己依序做。每項結論是 PASS 或 VETO 加一句理由。除基本面外不可上網、不可找新價格。

1. **動能**:只看「依據」那一行。30 日動能、日線/4H/1H 趨勢、資金費率是否支持這個方向?
2. **技術**:進場位的來源(括號內)是不是合理的壓力/支撐?停損是否在結構外?寫一句失效條件。
3. **基本面**:若「基本面:」那行說有快取且不要再查,只依快取判斷。否則用網頁搜尋(最多 3 次)查未來 24–48 小時:Fed 官員講話、美國 CPI/PPI/非農、交易所或監管風險、該幣的解鎖/升級。每個事實要有來源與日期,查不到就寫「查不到」。重大事件落在「掛單有效期 + 成交後 24 小時」內 → VETO。沒有搜尋工具就寫「未查基本面」,此項視為不通過也不否決,並在 --why 裡註明。另寫一段 100 字內摘要(風險低/中/高 + 最重要的 1–2 個事件與時間)。
4. **風控**:停損虧 ≤ 設定的單筆風險、槓桿 ≤ 上限、強平價離進場價的距離 ≥ 停損距離的 2 倍、TP1 賺賠比 ≥ 1,有一條不過就 VETO。資金費率:只有對持倉不利且絕對值超過 0.03% 才 VETO;小於這個值只在理由裡註記,不否決。

統整:風控或基本面 VETO → 否決;否則動能、技術、基本面三者至少兩者 PASS → 通過。然後執行其中一條(每項一句、總長 150 字內,不寫程式輸出以外的價位;這次沒上網查就不要帶 `--fund`):

```
python3 <本 skill 資料夾>/scripts/bot.py --confirm --why "技術:…/動能:…/基本面:…/風控:…" --diss "意見分歧或無" --fund "基本面摘要"
python3 <本 skill 資料夾>/scripts/bot.py --reject  --why "誰否決、為什麼(一句)" --diss "意見分歧或無" --fund "基本面摘要"
```

再照新輸出最後一行 `NEXT=` 做。被否決的方案 12 小時內不會再被提出。

## 程式的把關規則(回答「為什麼沒有方案」時用)
只做順勢回檔限價單(不做突破單);日線與 4H 趨勢同向;30 日動能同向;賺賠比(TP2) ≥ 2 且目標是實際支撐/壓力位;TP1 賺賠比 ≥ 1;4H 與日線 RSI12 未超賣(做空)或過熱(做多);24 小時成交額 ≥ 1,000 萬 USD;停損 ≥ 1 個 1H ATR;同時最多一張方案。掛單有效 6 小時,成交後最長持倉 24 小時,TP1 先平一半。股票永續不在範圍內。

## 狀態與設定放在哪
執行時的工作資料夾底下的 `trading-bot-state/`(可用環境變數 `BOT_STATE_DIR` 改):
- `config.json`:本金、風險、槓桿上限等設定(可手動改,鍵名同 `bot.py` 開頭的 `CFG`)。
- `state.json`:目前的方案、否決冷卻、基本面摘要。
- `out/`:每張通過的決策單(`decision_*.md`)與結束的假想單結果(`plan_*.json`)。

這個資料夾要保留,程式才能接著追蹤上一張方案。在不保留檔案的雲端環境裡,每次都會從零開始:要先告訴使用者「上一張方案的追蹤不會延續」,或請他提供上次的 `state.json` 放回去。

## 建議的執行頻率
一天 2–3 次即可(例如早、晚、睡前)。掛單有效只有 6 小時,所以每次方案都要當下就掛單並設好停損/停盈;太久沒跑(超過約 40 小時)會讓上一張方案的追蹤不完整。

## 復盤實單(選用)
使用者想檢討自己真的下過的單時,請他準備 CSV(欄位:`open_time,close_time,symbol,side,leverage,entry,exit,notional_usd,pnl_usdt,followed_report,stop_price,tp_price,planned_rr`,時間格式 `YYYY-MM-DD HH:MM`),然後:

```
python3 <本 skill 資料夾>/scripts/review.py trades.csv --out review.md
```

它會算勝率、平均 R、樣本是否足夠下結論、分組比較,以及逐筆是否違反槓桿與賺賠比規則。把輸出照實轉述,不要加上樂觀的解讀。
